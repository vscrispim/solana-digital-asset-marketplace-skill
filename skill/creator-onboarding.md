# Creator Onboarding

## Goal

Help marketplaces onboard creators manually, safely, and with enough context to publish assets without chaos.

## Intake questions

Ask creators for:

- display name;
- portfolio links;
- asset title;
- asset category;
- ownership confirmation;
- source files/formats;
- preview images/video;
- intended buyer;
- personal/commercial license preference;
- price range;
- support/update expectations;
- payout preference;
- restricted uses.

## Cybersecurity alerts

- Treat uploaded ZIPs, scripts, Blender add-ons, plugins, and executable-looking files as untrusted.
- Verify payout changes through a second channel; creator account takeover often shows up as a “new wallet/bank account” request.
- Keep an audit log when creators replace files after publication.
- Do not run creator-provided scripts during preview generation.

## Manual review

Before publishing:

- verify asset ownership signals;
- check whether third-party IP appears;
- check whether files open correctly;
- confirm license copy;
- create preview/poster;
- test download package;
- prepare support notes.

## Human onboarding principle

Creators should feel like the marketplace is helping them launch a better drop, not extracting files from them.

Use language like:

> We help package the asset, clarify the license, create a clean preview page, and test whether buyers care about protected delivery and receipts.

## Output format

Return a creator onboarding checklist, first message, and publication criteria.

## Safety boundary

This module is not legal, financial, or security advice. It helps structure founder decisions and prepare better questions for counsel, engineers, and operators.
